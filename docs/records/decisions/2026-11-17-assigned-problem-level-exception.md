# 스터디 배정 문제의 레벨 잠금 예외

- 상태: 채택
- 결정일: 2026-11-17
- 확인: B(문제·채점) 동의, C(모의 코테·대회) 확정 / D(스터디) 작성 / E(회원) 확인 요청
- 관련 작업: [Issue #757](https://github.com/Back-To-Back-team-3/re-solve/issues/757)

## 결정

개인 태그 레벨 잠금에 스터디 배정 문제 예외를 둔다.

- 활성 스터디원이 배정받은 문제는 Run·연습 제출 모두 개인 태그 레벨 잠금을 적용하지 않는다. 대상 조건과 판정 시점은 [정책 및 상태 §8.3 > 문제 접근 제한](../../dev/planning/policy-and-state.md#83-태그별-진단레벨-갱신)을 따른다.
- 시험·대회·진단 문맥에는 개인 태그 레벨 잠금을 적용하지 않는다.
- judge와 프론트는 레벨 잠금으로 판정했을 때만 study에 배정 여부를 확인하고, 확인에 실패하면 잠금을 유지한다. 계약은 [API 명세 §5.4.5·§5.7.4](../../dev/specifications/api-spec.md#545-배정-문제-레벨-잠금-예외-확인)를 따른다.
- 예외 제출의 문맥은 `PRACTICE`를 유지하고, 요청에 문제집 식별자를 넣지 않는다.

## 채택 근거

- 문제집은 스터디장이 스터디 수준에 맞춰 고른 공동 과제다. 개인 레벨 잠금이 그대로 걸리면 레벨이 낮은 대상자는 과제를 풀 수 없고 진행률이 오르지 않는다.
- 레벨 잠금으로 판정된 경우에만 확인하므로, 레벨 안의 문제에는 study 호출이 생기지 않는다.
- 제출 요청과 제출 문맥을 바꾸지 않아 judge 제출 계약·채점 이벤트·진행률 인정 기준(`PRACTICE` AC)이 그대로 유지된다.
- 시험·대회·진단은 출제자가 문제를 정해 응시하는 문맥이라 개인 레벨 잠금의 대상이 아니다. 현재 judge 동작과도 같다.

## 기각한 대안

- **리더 레벨 제한을 먼저 적용해 스터디 수준을 묶는 안**: 승급이 연동되기 전이라 태그 레벨이 실제 실력을 반영하지 못한다. 승급 연동 후 다시 검토한다(정책 및 상태 > `미결정 사항`).
- **요청에 문제집 식별자를 넣어 확인하는 안**: judge·프론트가 문제집 문맥을 계속 들고 다녀야 하고, 제출 요청 계약이 바뀐다.
- **스터디 구성원이면 모든 문제집 문제를 허용하는 안**(기존 초안 "레벨 제한 미적용"): 가입만으로 잠금이 풀리고, 진행률 대상자 기준과 어긋난다.

## 재검토 조건

- 승급 연동이 완료되면 예외 제출의 승급·성취도 집계 포함 여부와 리더 레벨 제한을 다시 검토한다.
- 스터디 수준별 문제집 난이도 상한을 도입하면 예외 범위를 다시 검토한다.
