# 기존 시드 문제의 실풀이 자료 등록

## 목적과 자료 보관

기존 V13~V15 시드는 문제·회차·테스트의 메타데이터를 만든다. 본문 자산의 체크섬·크기는 임시 값이며, 마이그레이션 실행만으로 실제 S3 파일이나 통과 실행 프로필이 생기지 않는다. 기존 마이그레이션을 고치거나 DB에 검증 성공을 직접 넣지 않고, 관리자 API로 같은 문제에 새 불변 회차를 등록해 보완한다.

문제 원본은 [Problem 시드 문제 구현](https://app.notion.com/p/dcfc4b3d7d9e8244b5b8813da1d81611)의 **v1.0 → 카테고리별 문제 전문**이다. 상단의 이전 샘플과 섞지 않는다. 문제 본문·숨김 테스트·정답/오답 코드는 정책 및 상태 > 문제 > 저장 방식에 따라 Git에 커밋하지 않는다. 비공개 입력 자료와 체크포인트도 저장소 밖의 지속 보관 경로에 둔다.

이 도구를 병합한다고 모든 환경의 S3에 자료가 자동 생성되지는 않는다. 적용할 환경마다 원본 자료를 준비하고 실행해야 한다. 로컬 S3가 초기화되면 체크포인트의 완료 표시만으로 복구할 수 없으므로 자료와 DB·S3 백업을 함께 관리한다.

## 입력 자료

`problem-service/scripts/materialize-seed-problems.py`는 비공개 JSON 배열을 받는다. 각 항목은 아래 구조를 사용한다.

| 필드 | 설명 |
| --- | --- |
| `problemId` | 기존 시드 문제 ID. 제목이 일치하는 GENERAL·PUBLIC 문제만 허용 |
| `content` | API 명세서 > Problem > 새 회차 등록의 전체 본문. `rowVersion`은 제외하고 도구가 최초 목록 조회 값으로 고정 |
| `solutions.ac` | Java 정답 코드 파일의 상대 경로 |
| `solutions.wa` | Java 오답 코드 파일의 상대 경로. 적어도 하나의 WA가 필요 |
| `solutions.re` | Java 실행 오류 코드 파일의 상대 경로. 적어도 하나의 RE가 필요 |

- 코드 파일 경로는 JSON 파일이 있는 디렉터리를 기준으로 해석한다.
- `content`에는 제목·설명·제약·입출력 예·난이도·태그·함수 명세·테스트를 모두 제공한다. 공개 예제와 숨김 테스트가 모두 필요하다.
- 테스트는 기존 API의 `isSample`, `argumentTexts`, `expectedReturnText`를 사용한다. 입력과 기대값은 TypeSpec에 맞는 JSON 텍스트로 준비한다.
- 정답 코드만 실행해 기대값을 생성하는 것으로 검증을 대체하지 않는다. 예제와 추가 테스트의 기대값을 별도 계산하고, 대안 풀이와도 대조한다.
- 태그 ID는 대상 환경의 태그와 확인한다. 문제 ID를 새로 발급하거나 제목이 다른 기존 문제를 덮어쓰지 않는다.

## v1.0 자료 보완 기준

| 대상 | 보완 |
| --- | --- |
| 문제 10 공개 예제 | 첫 예제의 최소 변동은 3이 아니라 2. 첫 구간의 최댓값−최솟값으로 확인 |
| 문제 26 공개 예제 | 세 스피커의 최대 최소 간격은 4가 아니라 3. 원문 설명의 계산과 일치시킴 |
| 문제 11 정답 코드 | `targetMask=0`이면 빈 선택으로 충족하므로 0 반환. 해당 경계 테스트 추가 |
| 문제 18 설명 | 워커 처리 능력치 **이하**의 요청을 처리한다는 조건으로 예제·풀이와 일치시킴 |
| 문제 15·20 반환 타입 | 입력 제약을 유지하고 INT64(`long`)로 보완. 완료 시각 합·병합 비용을 int로 누적하거나 잘라 반환하지 않음 |
| 위치별 정수 배열 | 원본 TypeSpec의 `positionTypes` 유지. 현재 Java 매핑에 맞춰 `Object[][]` 매개변수에서 `Integer` 값을 복원한 뒤 기존 알고리즘 호출 |

추가 테스트에는 최소 입력, 중복·동률, 마지막 구간, 공집합 목표, 빈 간선, 연결·단절, 사이클 배제, 정수 누적 범위 등을 포함한다. WA·RE로 이름 붙은 코드도 실제로 해당 실패를 유발하는 입력이 있는지 확인한다.

## 실행과 재개

Python 3.9 이상과 POSIX 파일 잠금을 지원하는 macOS·Linux에서 실행한다. 실제 Problem 내부 API와 메시지 발행·수신·Judge 검증 실행이 연결된 테스트 환경, 작성 관리자 토큰, 대상 환경의 S3·큐를 준비한다. 별도 환경 변수는 추가하지 않는다.

```sh
# 비공개 입력 파일 전체 확인. 서버에는 요청하지 않는다.
python3 -B problem-service/scripts/materialize-seed-problems.py \
  http://localhost:8080 /private-data/catalog.json /private-data/checkpoint.json --check-only

# 토큰은 프롬프트에 입력하며 파일이나 명령행 인자로 저장하지 않는다.
python3 -B problem-service/scripts/materialize-seed-problems.py \
  http://localhost:8080 /private-data/catalog.json /private-data/checkpoint.json
```

도구는 관리자 목록으로 모든 대상의 제목·상태를 먼저 확인한 뒤 아래 순서로 처리한다.

1. 최초 `rowVersion`과 안정적인 멱등키를 체크포인트에 보존하고 새 회차를 등록한다. API가 S3 파일과 실제 체크섬·크기·버전을 저장한다.
2. WA → RE → AC 순서로 검증을 접수한다. Problem이 종결 결과를 반영할 때까지 기다리고 테스트 개수와 개별 판정을 확인한다.
3. 현재 회차·통과 회차가 등록한 회차인지, PUBLIC 상태와 Java 실행 프로필이 유지되는지 확인한다. 공개 상태를 별도로 강제 변경하지 않는다.

응답 유실·조회 타임아웃은 **같은 자료·서버·체크포인트**로 재개한다. 최신 `rowVersion`으로 요청을 다시 만들지 않는다. 검증이 반영된 ERROR로 끝났을 때만 `--validation-attempts 2`처럼 시도 한도를 늘려 새 검증을 접수한다. 판정 불일치·409·422를 새 키로 자동 우회하지 않는다.

체크포인트에는 원문·코드·토큰을 저장하지 않는다. 동일 체크포인트를 사용하는 프로세스의 동시 실행은 파일 잠금으로 차단한다. 자료나 서버가 바뀌면 기존 체크포인트를 거절한다. 최초 요청에서 24시간이 지나면 미완료 요청의 자동 재개를 중단하므로 관리자에서 접수 상태를 먼저 확인한다. 체크포인트를 지우고 무작정 재실행하지 않는다.

공개 예제와 숨김 테스트가 Java 검증을 통과해도 Python·C++ 실행 프로필까지 생기지는 않는다. 해당 언어를 제공하려면 같은 회차에 언어별 정답 코드를 별도로 검증한다.

## 도구 회귀 테스트

```sh
python3 -B -m unittest discover -s problem-service/scripts -p 'test_*.py' -v
```

실제 환경 검증에서는 새 회차·세 종류 검증의 접수 ID를 보관하고 관리자 조회·사용자 상세 조회까지 확인한다. 비공개 테스트 입력과 코드가 포함된 응답 본문은 PR·실행 로그에 첨부하지 않는다.
